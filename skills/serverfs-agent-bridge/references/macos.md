# macOS host Bridge

Use `deployment/macos/README.md` and primary Skill gates. Native arm64 signed SMAppService; keep owner state, provider credentials and runtime private.

**Owned:** same instance ID for Core and dedicated Bridge. Choose owned mode before staging; `owned-preflight`, `owned-stage`, `owned-policy-check`, `owned-start`, `owned-status`. Default v1 derives private policy from TOML and native manifest/socket checks. New Owned instances can explicitly select signed v2 with `owned-stage --agent-protocol v2`; use per-alias grants and do not switch an existing instance in place. Use actual derived socket path. Named owned staging does not pass the legacy Jev private overlay. Stage is create-only, not live reconfiguration.

**Shared:** independently provisioned v2 owner required; no general owner installer through shared CLI. Owner issues per-Core grant and private binding from actual workdir policy digest, not TOML hash. v0.26.0 supports 1–16 explicitly owner-bound Agent aliases (schema 1 for one alias, schema 2 for multiple). Existing single-alias grants are not silently expanded. Additional disjoint file-only workdirs allowed; no Repo Ops or named Connector staging. Use a pinned, compatible runtime. For Qoder, the demonstrated SDK 1.0.15 / bundled CLI 1.1.61 combination can be selected explicitly with `qoder_bin`; verify compatibility rather than assuming the newest host CLI works. Use `shared-stage`, `shared-preflight`, `shared-start`, `shared-status` with exact `--bridge-id`. Owner can be offline during staging but must be ready/authorize at activation. Signed v2 rejects continuation/idempotency. Shared Core never operates owner.

Respect Login Items approval and active Connector stop guards. Verify Core and only requested Bridge capabilities; no default-owner group operations, forced unstage or lease removal.
