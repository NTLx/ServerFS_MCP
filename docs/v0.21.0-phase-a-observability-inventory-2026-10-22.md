# ServerFS v0.21.0 Phase A — Observability Surface Inventory

Status: **Phase A inventory complete.** This record inventories existing operational signals and freezes the input contract for Phase B. It does not add a status API, exporter, listener, telemetry backend, or runtime authority.

Baseline: v0.20.0 implementation accepted; repository state after `docs: accept v0.20 implementation` (`1de9428877d404a2c8b6f4b01d2ba18c41b94505`). Current stable release remains v0.19.0; v0.20.0 is not released.

Date: 2026-10-22.

## 1. Decision summary

The repository already has useful observability facts, but they are intentionally split across operator diagnostics, platform lifecycle managers, Tunnel health, Bridge persistence, and read-only host publication. v0.21 should **normalize meaning**, not force those implementations into one service or protocol surface.

Phase B is therefore frozen to these rules:

1. Build **one internal versioned observation model first**. Do not start with Prometheus, OpenTelemetry, a new HTTP endpoint, or a public MCP tool.
2. `configured` is not `healthy`; `registered` is not `ready`; process existence is not downstream reachability.
3. Preserve explicit `observed`, `configured`, `not_checked`, and `stale` provenance. Unknown or failed inspection must never silently become healthy.
4. Preserve platform-native lifecycle implementations. Windows Task Scheduler/watchdog state and macOS ServiceManagement/LaunchAgent state map into common semantics but remain separate implementations.
5. Keep deep diagnostics where they already belong. Tunnel component health, `doctor`, native service status, and Bridge task APIs are not collapsed into one giant dump.
6. Common status and metric dimensions must not contain task IDs, correlation/idempotency IDs, provider session IDs, workdir aliases/paths, usernames/principals, model IDs, hostnames/IPs, URLs, filenames, prompts, file content, raw exception strings, executable paths, or environment values.
7. No new network listener or outbound telemetry is justified by Phase A. Exporter selection remains postponed until the internal model and operator projections are stable.
8. No performance budget is claimed as measured by this inventory. Baseline performance measurements remain **Not measured** and must be established before Phase D hot-path instrumentation is accepted.

## 4. Proposed Phase B internal observation contract

Phase A does **not** freeze serialized public JSON. It freezes the semantic minimum that Phase B must encode and test.

### 4.1 Snapshot identity

Required internal fields:

- `schema_version` — internal observation-contract version;
- `observed_at` — UTC timestamp generated by the collector/adapter;
- `product_version`;
- `process_role` — bounded enum such as MCP/native-service/bridge/tunnel-summary where applicable;
- `platform_family` — bounded `linux`, `windows`, `darwin`.

Do not include hostname, username, PID, command line, environment, install path or configuration path in the shared snapshot.

### 4.2 Component observation

Each component needs closed enums for:

- applicability/config state: `enabled`, `disabled`, `not_applicable`, `unsupported`;
- health: `healthy`, `degraded`, `unavailable`, `unknown`;
- provenance: `observed`, `configured`, `not_checked`, `stale`;
- stable bounded reason code;
- observation timestamp/freshness.

Details, if any, must be typed and explicitly allowlisted per component. Free-form exception/provider/config text is not part of the internal contract.

### 4.3 Overall aggregation

Phase B must implement deterministic tested precedence. Minimum rule:

1. A required component observed unavailable can make the declared role `unavailable`.
2. A required component degraded or unverified can make the role `degraded`/`unknown` according to role policy.
3. Disabled/not-applicable optional components do not degrade the role.
4. Configured-but-not-probed components remain `not_checked`/`unknown`; they are never promoted to healthy.
5. Stale observations remain stale and cannot satisfy current readiness.

Liveness, readiness and health remain distinct projections. Observation collection never performs repair, authorization, provider work or filesystem mutation.

## 6. Compatibility and security constraints for Phase B

- Existing MCP schemas and tools do not change for observability.
- `serverfs doctor` remains an explicit read-only diagnostic command and keeps stdout free for MCP protocol use.
- Existing human/native lifecycle status outputs remain available even if a sanitized common projection is added later.
- Windows status paths/PIDs/task metadata and macOS app/log paths/PIDs do not enter the common contract.
- Bridge state remains private. Common aggregation never copies prompts, results, provider payloads, native session IDs or arbitrary error messages.
- Tunnel health/admin interfaces remain private to their existing topology; Phase B adds no publication or auth exception.
- Host-observability collection remains outside ServerFS core; no shell, Docker socket or broad log access is added.
- No persistent schema/data migration is needed for Phase B; the common model is derived/read-only state.

## 7. Performance baseline

**Not measured in Phase A.** The bounded inventory task did not establish a reliable reproducible startup/RSS/idle CPU/request-latency baseline, and this record does not manufacture one from incidental command timing.

Before Phase D adds always-on counters/timing to hot paths, capture reproducible before/after measurements on reference environments. Phase B itself should remain pure/derived and have no background thread, polling loop, network dependency or persistent event store, making disabled/exporter-free overhead structurally minimal.

## 8. Open implementation decisions entering Phase B

The following decisions remain deliberately narrow:

1. Exact Python type representation: dataclass/enum versus Pydantic. Prefer standard-library immutable dataclasses/enums unless schema validation materially benefits from Pydantic already present in the root dependency graph.
2. Exact component key set and bounded reason-code enum. Derive keys only for inventory domains actually implemented; do not create placeholder provider-specific keys.
3. Exact aggregation precedence between `degraded` and `unknown` for a required `not_checked` component. Freeze one deterministic role-policy table in tests.
4. The narrowest later CLI projection. Do not decide this in Phase B; Phase C should reuse an existing admin surface rather than creating a network endpoint.
5. Exporter choice remains **deferred**. No Prometheus/OpenTelemetry dependency or listener is justified by this inventory.

## 9. Phase A gate verdict

**PASS.** Every observation domain planned for Phase B has an identified existing source or an explicit unsupported/not-checked state, along with ownership, sensitivity and applicability constraints. The inventory does not require a duplicate status service or exporter assumption.

Phase B may proceed with an internal-only, versioned, redacted observation contract and deterministic contract tests. Performance measurement remains an explicit later prerequisite before Phase D hot-path instrumentation, not a fabricated Phase A success claim.
