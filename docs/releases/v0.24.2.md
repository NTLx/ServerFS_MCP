# v0.24.2 — Windows-native Cloudflare Tunnel (release candidate)

> **Status: RELEASE CANDIDATE; NOT PUBLISHED.** No `v0.24.2` tag, GitHub Release, GHCR image or Plugin ZIP is claimed. The real public SSE beyond-60-second gate passed (75.0/70.0/65.0-second holds with approximately 15-second keepalives, same-session 27-tool `tools/list` 200, and new-session 200). Final exact-SHA CI and architecture-equivalent full-generation recovery evidence remain pending. v0.24.1 remains the published stable release.

## Intended changes

- Add optional Windows 11 x64 Cloudflare ingress for ServerFS native Streamable HTTP, using the existing current-user Task Scheduler 2.0 → watchdog → runner lifecycle and one kill-on-close Windows Job Object containing the HTTP Origin and cloudflared Connector.
- Preserve OpenAI Tunnel as the default Windows provider. The accepted topology uses two independent same-user Task Scheduler owners: OpenAI default and `ServerFS Cloudflare WorkPC` via `service cloudflare-parallel`. Each has separate venv/state/watchdog/runner and may share the same writable workdirs and one Agent Bridge/Repo Ops service. The older single-owner provider guard remains scoped to that owner; it does not prohibit independent owners. There is no universal automatic handover. Keep the shared Agent Bridge running if Cloudflare still depends on it after OpenAI is retired.
- Add a pinned official Windows x64 cloudflared `2026.10.7` bootstrap with full SHA-256 digest, Authenticode publisher and executable version checks.
- Add fail-closed private Windows credential file validation: current-user SID/owner, protected DACL, symlink/junction/reparse rejection and locations outside configured workdirs/checkout. Raw Tunnel Token is never passed as an argument; the Connector uses `--token-file`.
- Require independent ServerFS HTTP API Key or OAuth, an explicit exact public Host allowlist, 127.0.0.1 binding, and HTTP anonymous 401 readiness before starting the Connector.
- Add provider-specific status/child liveness, crash/recovery tests, Windows native HTTP subprocess acceptance, and dual-language operator/site/Agent Skills guidance without changing filesystem policy, Repo Ops or Agent Bridge authority.

## Compatibility and limitations

- One Windows service owner selects one Tunnel provider. The accepted independent owners can run together; there is no universal automated provider handover. No lossless session replay guarantee is made.
- macOS native Cloudflare (v0.24.1) continues to use its own Apple SMAppService lifecycle. Linux Docker Cloudflare (v0.24.0) remains outbound-only inside its documented Docker networks.
- Windows requires a user-level version-matched `serverfs-mcp` + `serverfs-windows-native` installation, current-user-private Tunnel Token and HTTP Origin environment files, and a separately managed Cloudflare hostname/tunnel.
- Public ChatGPT acceptance passed HTTPS 401/200, tool calls, cross-ingress read/write/edit/delete on shared writable workdirs, and Codex/Claude through the two owners. The >60-second public SSE gate passed: three holds lasted 75.0, 70.0, and 65.0 seconds with approximately 15-second keepalives; same-session `tools/list` returned 200 with 27 tools and a new session returned 200. Windows HTTP origin and cloudflared share one kill-on-close Job generation; Connector failure is expected to tear down the full generation for bounded restart; this recovery remains unverified. Recovery must be verified with a fresh MCP session. This is architecture-equivalent Windows acceptance, not a Connector-only restart pass; an older in-memory session is not guaranteed to survive or replay. Qoder's provider error predated this acceptance; Python urllib's default User-Agent received edge WAF 1010, an edge configuration caveat.
- Do not replace or reconfigure the continuously used OpenAI owner for Cloudflare testing. The accepted setup used a separate Cloudflare owner alongside it.
