# ServerFS v0.23.0 — Deterministic Repo Ops

v0.23.0 adds a generic, deterministic repository-operations surface for opted-in **Linux ServerFS workdirs**. The new capability is deliberately separate from Agent delegation: ChatGPT or another MCP client can finish bounded repository work without receiving a shell and without submitting a server-side AI Agent task.

## Highlights

- **Four public Repo Ops tools**: `inspect_repo`, `run_repo_action`, `commit_repo_changes`, and `push_repo`.
- **Independent per-workdir gate** via `WORKDIR_XX_REPO_OPS_ENABLED=true`; Repo Ops can be enabled while Agent mode remains disabled.
- **Deterministic named actions** use operator-owned fixed policy, mandatory SHA-256 integrity pins, a narrow child environment, bounded execution, and the shared writer lease.
- **Hardened Git commit/push paths**: explicit commit paths only, no pre-existing staged state, external content filters rejected, hooks/signing disabled on the deterministic path, and push restricted to the derived current upstream with one exact refspec.
- **Fixed release actions** are supported for operator-configured repositories: `release_tag` can create/push a validated release tag at the captured clean `main` HEAD, and `publish_npm` can dispatch one fixed GitHub Actions publication workflow without exposing generic Git/workflow arguments.
- **No Agent fallback**: Repo Ops never selects a model/runtime, creates an Agent task/session, or invokes a provider adapter.

## Security boundary

Repo Ops does **not** add a generic shell, command executor, caller-controlled executable/argv/environment, arbitrary remote/ref selection, or force semantics. All caller paths pass ServerFS policy, the Host Bridge independently confines host paths, and every named action verifies operator-pinned repository inputs immediately before execution while holding the existing writer lease.

The v0.23.0 Repo Ops release scope is **Linux Host Bridge deployments**. Native Windows/macOS Repo Ops enablement is not claimed. Existing Windows/macOS filesystem and Agent deployment contracts remain supported and were regression-tested for this release.

## Upgrade notes

Production Linux deployments should pin `ghcr.io/ntlx/serverfs_mcp:0.23.0`. Repo Ops remains disabled unless explicitly enabled for a workdir. Enabling Repo Ops requires the authenticated Host Bridge transport (`compose.agent.yml` on Linux) but does **not** require enabling an Agent runtime.

When configuring named actions, treat integrity-pin updates as an explicit operator review decision. Do not automatically refresh a pin in the same task that changed the pinned repository code.

The release workflow attaches the product wheel, Agent Bridge wheel, Windows native abi3 wheel, and the skills-only `serverfs-plugin-v0.23.0.zip`; their SHA-256 values are appended automatically to the GitHub Release body after the tag workflow completes.
