# v0.26.0 — Scoped approval audit and restored named-runtime capabilities

**Candidate — not released.** The stable distribution remains v0.25.0. This document describes the intended v0.26.0 source and recorded development evidence; it does not authorize a tag, deployment, or migration. See the [development plan](../../dev_plan_v0.26.0.md) and [release checklist](../v0.26.0-release-checklist.md).

## Changes

- Shared Agent Bridge: retain private, task-bound keyed identities for original approval requests before public redaction, with action and resolution metadata. Recognized outside-workdir writes cannot be approved remotely. Redacted public labels are not resource identities; optional Jev advice never authorizes execution.
- Linux named signed-v2 Core: explicitly grant 1–16 Agent and/or Repo Ops workdirs across slots 01–16. Agent and Repo Ops remain independent. Each Core's binding and owner grant restrict the selected aliases and policy revisions; unrelated roots remain disjoint. Core and Connectors remain Docker Compose components; Bridge remains optional and host-native.
- macOS Shared Core: bind 1–16 owner-authorized Agent workdirs against an existing independent Bridge owner, including scoped follow-up routing. Shared Repo Ops and named Connector staging remain unsupported; native owned-mode behavior is not replaced.
- Windows named Bridge: explicit runtime/ACP proxy opt-in through the protected owner-private bootstrap and bounded credentialless proxy configuration. Direct runtimes do not inherit ambient proxy settings. Connector and Jev egress are separate. Native Task Scheduler, Job Object, Named Pipe and ACL boundaries remain.
- Updated bilingual README/site, operational Skills, deployment examples and maintainer invariants; added Windows loopback-traffic regression to the candidate CI test list.

## Compatibility and migration

Use matching source, Core/Bridge/native wheels, image and Plugin versions. Existing v0.25.0 single-alias bindings remain versioned; a new multi-alias binding must be provisioned with matching per-alias owner policy and explicit grants. For macOS shared mode use schema 1 for a single alias or schema 2 for multiple aliases; for Linux use the documented versioned binding and slot mapping. Do not silently convert, copy or broaden an existing grant. The Windows helper remains create-only; proxy opt-in requires a matching private file and enabled runtime. The older version's tagged guide remains authoritative for existing v0.25.0 artifacts.

Keep v0.25.0 installed binaries, private configuration and provider state intact. Create disposable independent instances with non-overlapping identifiers, roots, ports, Compose project names, owner endpoints and caller credentials. Verify authorized and denied behavior before any explicit cutover. On failure, stop and retire only disposable components in dependency order after proving active-task and writer-lease safety; preserve evidence and verify original service health. No implicit in-place migration, credential rotation, live grant append or automatic rollback is promised.
