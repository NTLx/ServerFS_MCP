# v0.26.0 — Scoped approval audit and restored named-runtime capabilities

v0.26.0 restores multi-workdir named Agent/Repo Ops capabilities, adds scoped task discovery and private approval auditing, and supports explicit named Windows runtime proxy policy. The independently managed Core, Connector and optional host Bridge model is unchanged. Use the [platform guides](../../README_EN.md#choose-a-platform) and matching artifacts for new deployments; see the [release checklist](../v0.26.0-release-checklist.md) and [evidence ledger](v0.26.0-evidence.md) for measured acceptance.

## Changes

- Shared Agent Bridge: retain private, task-bound keyed identities for original approval requests before public redaction, with action and resolution metadata. Recognized outside-workdir writes cannot be approved remotely. Redacted public labels are not resource identities; optional Jev advice never authorizes execution.
- Linux named signed-v2 Core: explicitly grant 1–16 Agent and/or Repo Ops workdirs across slots 01–16. Agent and Repo Ops remain independent. Each Core's binding and owner grant restrict the selected aliases and policy revisions; unrelated roots remain disjoint. Core and Connectors remain Docker Compose components; Bridge remains optional and host-native.
- macOS Shared Core: bind 1–16 owner-authorized Agent workdirs against an existing independent Bridge owner, including scoped follow-up routing. Shared Repo Ops and Shared Connector staging remain unsupported.
- macOS named Owned Core: new instances may explicitly select signed v2 using `owned-stage --agent-protocol v2`. Independent per-alias grants support Agent and Repo Ops policies; Repo-only aliases do not receive task methods, and read-only Repo aliases receive inspection only. Existing v1 remains the default. Named Cloudflare/OpenAI Connector staging uses the existing owner-private validation and native launcher.
- Signed-v2 task discovery on Linux, macOS and Windows: `list_agent_tasks(workdir, status="active", limit=20, cursor=None)` returns a bounded page of authorized task metadata and an opaque next cursor. Use the exact Agent-enabled alias; status accepts active, terminal or all, and limit accepts 1–100. Core identity, alias, key and policy revision bind the cursor and ownership checks. Fresh MCP clients can recover retained task IDs without the original submission response; legacy or foreign task ownership is not inferred. No global listing or v1 fallback.
- Windows named Bridge: explicit runtime/ACP proxy opt-in through the protected owner-private bootstrap and bounded credentialless proxy configuration. Direct runtimes do not inherit ambient proxy settings. Connector and Jev egress are separate. Native Task Scheduler, Job Object, Named Pipe and ACL boundaries remain.
- Updated bilingual README/site, operational Skills, deployment examples and maintainer invariants; added Windows loopback-traffic regression to the CI test list.

## Compatibility and migration

Use matching source, Core/Bridge/native wheels, image and Plugin versions. Existing v0.25.0 single-alias bindings remain versioned; a new multi-alias binding must be provisioned with matching per-alias owner policy and explicit grants. For macOS shared mode use schema 1 for a single alias or schema 2 for multiple aliases; for Linux use the documented versioned binding and slot mapping. Do not silently convert, copy or broaden an existing grant. The Windows helper remains create-only; proxy opt-in requires a matching private file and enabled runtime. The older version's tagged guide remains authoritative for existing v0.25.0 artifacts.

Task discovery requires both the signed-v2 Core client and Bridge to support the method and an explicit owner grant containing `task.list` and `task.get`. Existing grants are not silently expanded. Legacy v1 task-by-ID operations remain unchanged, and old unowned task records are not retroactively attributed. Signed-v2 submission does not support `continue_from_task_id` or `idempotency_key`; do not replace a working v1 deployment if it requires these features. On macOS provision a new named Owned v2 instance rather than changing an existing instance's protocol or reusing its private state. Shared Repo Ops remains unsupported. Verify the actual requested Connector/provider combinations before cutover.

Keep v0.25.0 installed binaries, private configuration and provider state intact. Create disposable independent instances with non-overlapping identifiers, roots, ports, Compose project names, owner endpoints and caller credentials. Verify authorized and denied behavior before any explicit cutover. On failure, stop and retire only disposable components in dependency order after proving active-task and writer-lease safety; preserve evidence and verify original service health. No implicit in-place migration, credential rotation, live grant append or automatic rollback is promised.

## Acceptance evidence

For the frozen product source, real multi-workdir Agent execution and task rediscovery were verified on Linux, macOS and Windows. Core restart recovery was verified; the Windows dual-workdir run also recovered results after Bridge restart. Real Cloudflare file-only ingress was exercised on all three platforms. Windows named proxy rejection reached the configured Bridge deadline and returned `AGENT_TASK_TIMED_OUT` without an external cancellation. macOS Qoder acceptance used SDK 1.0.15 and its compatible bundled CLI 1.1.61. These are scoped results, not guarantees for every provider, ingress or topology. See the evidence ledger for exact hashes, conditions and limitations.
