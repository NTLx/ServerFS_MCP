# ServerFS v0.23.3 — Release-Gated Native Windows Repo Ops

ServerFS v0.23.3 is the release-hygiene patch that completes the v0.23 Windows native Repo Ops rollout as a fully gated stable release.

The Windows product behavior introduced in v0.23.2 is retained unchanged: validated native Windows 11 x64 Repo Ops remains independently gated from Agent delegation, current-user/non-elevated, local-NTFS constrained, and fail-closed. v0.23.3 fixes the publication process defect exposed by v0.23.2, where root Ruff failures could coexist with a published GitHub Release because tag-time publication ran independently from the full cross-platform validation matrix.

## Stable-release gate closure

Starting with v0.23.3, ServerFS stable publication is dispatch-first rather than tag-first:

- the Release workflow is started explicitly on `main` with the intended `vMAJOR.MINOR.PATCH` tag;
- the exact candidate SHA must pass Linux/Container + Agent Bridge + MCP conformance, Windows Native, Windows Agent, macOS Native, and Pages build gates;
- after the gates complete, `origin/main` is checked again and any intervening main advance fails closed;
- only the fully validated SHA may receive the lightweight stable tag;
- wheels, the Agent Plugin, GitHub Release, and stable GHCR tags are downstream of that tag creation;
- ordinary tag pushes no longer act as independent stable-release publishers.

This converts release discipline from a maintainer convention into an executable repository contract.

## Windows Repo Ops baseline

v0.23.3 preserves the v0.23.2 native Windows containment and public MCP contract:

- NTFS reparse points/junctions are rejected before Repo Ops execution;
- Repo Ops children are assigned to the Bridge-owned Windows Job Object before execution;
- timeout/cancellation/output-overflow cleanup proves descendant-tree termination before writer-lease release;
- uncertain cleanup fails closed and preserves the writer lease until Bridge generation restart;
- Git-for-Windows runs non-interactively with hardened fixed configuration;
- the public surface remains exactly `inspect_repo`, `run_repo_action`, `commit_repo_changes`, and `push_repo`, with no generic shell or caller-controlled executable/argv/environment/remote/ref/force surface;
- Repo Ops never falls back to Agent delegation.

The original Windows live acceptance remains recorded in [`v0.23.2 Windows Repo Ops acceptance`](../v0.23.2-windows-repo-ops-acceptance-2026-10-28.md). v0.23.3 publication additionally requires the full exact-SHA release matrix to be green before tag creation.

## Platform boundary

- Linux Host Bridge Repo Ops: v0.23.0+
- Validated native Apple Silicon macOS Repo Ops: v0.23.1+
- Validated native Windows 11 x64 Repo Ops: v0.23.2+

v0.23.3 does not expand the supported platform boundary; it makes that already validated Windows capability a clean, fully gated stable release.
