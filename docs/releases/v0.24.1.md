# ServerFS v0.24.1 — Native macOS Cloudflare Tunnel

## Native macOS Cloudflare Tunnel

v0.24.1 adds an optional native Cloudflare Tunnel ingress for Apple Silicon Macs running macOS 27.x. A dedicated HTTP origin binds to loopback, and a `cloudflared` Connector connects to an operator-configured remotely managed Tunnel. Bootstrap verifies the pinned official macOS arm64 artifact. The origin enforces the exact configured public Host and independent ServerFS API Key or OAuth caller authentication; the Tunnel Token authenticates only the Connector.

The Connector Token and HTTP-origin environment source are current-user files with mode `0600`, stored outside the checkout and every configured workdir. The origin and Connector use the same app-associated `SMAppService` LaunchAgent mechanism as the existing OpenAI Tunnel and Agent Bridge. This is Login Items architecture parity; no logout/login or whole-machine reboot was performed.

The existing OpenAI Secure MCP Tunnel, Agent Bridge, and Linux Docker Cloudflare ingress shipped in v0.24.0 remain available. Native Windows Cloudflare remains planned for v0.24.2. ServerFS does not provision Cloudflare Tunnels or DNS routes. See the [macOS native deployment runbook](../../deployment/macos/README.md#optional-cloudflare-tunnel-v0241) for CLI syntax, service lifecycle, staging, rollback, and operator acceptance.

## Recorded macOS staging evidence

On the supported macOS 27 Apple Silicon staging host, isolated read-only staging produced the following results:

- Public HTTPS returned **401** without caller authentication and **200** with the configured identity.
- MCP discovery exposed **11 tools**. A fixture read succeeded; write attempts, traversal, absolute paths, and hidden paths were rejected.
- A persistent SSE connection remained usable for **65.1 seconds** with keepalives.
- After a controlled Connector-only restart, the prior session returned **404**; a new session recovered successfully in **8/8** checks. This does not demonstrate old-session continuity or replay of SSE events in flight.
- Cloudflare and HTTP-origin services reached enabled state. Local stop/start and service persistence succeeded. Existing OpenAI Tunnel and Agent Bridge remained undisturbed.
- Source and contract review found the same `SMAppService.agent(plistName:)`, app-owned ServiceLauncher, and LaunchAgent restart policy as the accepted native services. This is architecture review, not an actual logout/login or reboot test.

These results describe isolated, read-only staging only. They do not establish production workdir, Agent, or Repo Ops acceptance. The operator's sanitized evidence is private and is not reproduced here; this note contains no user-specific hostname, username, IP address, Token, or credential.
