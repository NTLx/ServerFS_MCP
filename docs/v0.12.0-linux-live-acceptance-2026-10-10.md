## Codex 0.162.1 listener compatibility regression

During live acceptance, proxied Codex initially failed with `AGENT_RUNTIME_NOT_READY` even though the child process was alive. Diagnosis proved that Codex 0.162.1 changed the `--listen unix://PATH` shape: the requested listener path becomes a symlink to a same-user private Unix socket under `/tmp/codex-daemon-<uid>/...` rather than being the socket inode itself.

The pre-fix readiness check used `lstat()` + `S_ISSOCK()` on the requested path and therefore rejected the healthy listener until the 30-second startup timeout killed it. Raw Codex probes independently showed the listener appearing in under one second.

The fix keeps fail-closed semantics while accepting the provider-supported indirection only when the fixed listener path resolves through an absolute symlink to a real Unix socket owned by the current user in a current-user-owned, non-group/world-writable parent directory. Direct socket listeners remain accepted. Arbitrary symlinks are not accepted.

Post-fix unit coverage is **7 passing Codex Linux runtime tests**, Ruff is clean, and the live proxied Codex provider turn above completed with **14 external CONNECTs / 0 loopback**.
