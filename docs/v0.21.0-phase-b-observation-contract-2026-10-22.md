# ServerFS v0.21.0 Phase B — Internal Observation Contract

Status: **Phase B implementation complete; focused contract gate PASS.** This phase adds only an internal, standard-library observation model and deterministic contract tests. It adds no CLI surface, MCP tool, HTTP listener, exporter, dependency, collector, background thread, persistent schema, or new authority.

Baseline: Phase A inventory commit `3a36d42916e30b3ae965acf30804be50c2edb856`.

Date: 2026-10-22.

## 1. Implemented scope

Phase B implements the semantic contract frozen by the Phase A inventory in:

- `src/serverfs_mcp/observability.py`
- `tests/test_observability_contract.py`

The module is deliberately pure and derived. It receives already-authorized facts from future adapters; it does not collect operating-system state itself and cannot repair, start, stop, probe remote services, mutate files, authorize requests, or expose a network surface.

## 2. Representation decisions

### 2.1 Standard-library immutable types

The contract uses `dataclass(frozen=True)` and `StrEnum`. No Pydantic or new schema dependency was introduced because Phase B needs only a small closed internal vocabulary and deterministic validation.

The snapshot carries only:

- internal `schema_version`;
- `observed_at` UTC timestamp;
- bounded `product_version`;
- bounded `process_role`;
- bounded `platform_family`;
- one observation per bounded component key.

It intentionally has no hostname, username, PID, path, endpoint, command line, environment, task ID, session ID, prompt, result, arbitrary detail string, or exception payload.

### 2.2 Component vocabulary

The bounded component set matches the Phase A inventory domains:

- MCP transport;
- authentication;
- workdirs;
- Tunnel;
- file ingress;
- OAuth broker;
- Agent Bridge;
- Agent runtime;
- Agent tasks;
- writer lease;
- recovery.

Applicability is one of `enabled`, `disabled`, `not_applicable`, or `unsupported`.

Health is one of `healthy`, `degraded`, `unavailable`, or `unknown`.

Provenance is one of `observed`, `configured`, `not_checked`, or `stale`.

Reasons are a finite `ReasonCode` enum. The model has no free-form detail field. Future adapters must map raw operating-system/provider errors to a reviewed bounded reason before constructing the common observation.

## 3. Fail-closed semantics

The contract enforces the following invariants in code and tests:

1. `healthy` requires directly `observed` evidence.
2. `configured` and `not_checked` cannot assert current health.
3. `stale` evidence cannot assert current health.
4. Disabled, not-applicable, and unsupported components have `unknown` health and a matching explicit reason.
5. Duplicate component observations are rejected.
6. A component observation cannot be newer than its enclosing snapshot.
7. Unknown future component keys are rejected because they cannot safely inherit an existing component policy.
8. Unknown future health/provenance/applicability/reason values fail closed into `unknown`, `not_checked`, `unsupported`, or `unknown_value` semantics; they are never promoted to healthy.

These rules make “configured is healthy” and “unknown is healthy” structurally impossible inside the shared model.

## 4. Aggregation contract

`RolePolicy` supplies the required components for three independent projections:

- liveness;
- readiness;
- health.

The observation module does **not** hard-code one global deployment policy because applicability depends on the declared deployment role and platform/configuration. Platform/role adapters in later phases must select an explicit policy rather than inheriting assumptions from another platform.

The deterministic aggregation precedence is:

1. missing required component → `unknown / required_component_missing`;
2. required `unavailable` → `unavailable / required_component_unavailable`;
3. required `degraded` → `degraded / required_component_degraded`;
4. required `unknown`, `configured`, `not_checked`, or `stale` → `unknown / required_component_unknown`;
5. otherwise the required set is healthy;
6. only the health projection considers enabled optional components;
7. optional degraded/unavailable → overall health `degraded`;
8. optional unknown/unverified/stale → overall health `unknown`;
9. disabled/not-applicable optional components do not degrade the role.

The contract tests freeze this behavior with a representative policy in which MCP transport is sufficient for liveness, workdir readiness is additionally required for readiness/health, and Tunnel/Bridge are optional health components. That fixture freezes aggregation semantics, not a universal deployment configuration; real adapters remain responsible for selecting their required/optional sets explicitly.

## 5. Metric catalog and cardinality policy

Phase B also freezes the transport-neutral metric catalog proposed in Phase A:

- `serverfs_component_state`
- `serverfs_component_probe_total`
- `serverfs_agent_tasks_total`
- `serverfs_agent_task_duration_seconds`
- `serverfs_agent_queue_depth`
- `serverfs_agent_queue_wait_seconds`
- `serverfs_agent_lease_acquisitions_total`
- `serverfs_agent_lease_wait_seconds`
- `serverfs_agent_recovery_total`
- `serverfs_tunnel_state`

This is a semantic catalog only. No Prometheus/OpenTelemetry representation, listener, scrape endpoint, bucket set, exporter dependency, or telemetry egress exists in Phase B.

Every dimension has a finite allowlisted value domain. Dimension names containing sensitive/high-cardinality identity classes such as task, workdir, path, user/principal, model, session, correlation/idempotency, host/IP/URL, file, prompt, error, or exception are rejected by the model. Runtime is reduced to the bounded families `codex`, `claude`, `qoder`, `acp`, or `unknown`; arbitrary ACP profile names and model identifiers are not dimensions.

Each metric definition computes a maximum possible series count from its closed dimension domains. The complete catalog must remain under the process-level `MAX_METRIC_SERIES` ceiling of 10,000 or module import fails. Label validation requires an exact dimension set and allowlisted values.

This is a cardinality safety contract, not proof that Phase D will instantiate every possible series. Phase D should emit only series corresponding to real observed events/state.

## 6. Serialization and compatibility

The current serialized dictionary shape is internal contract data, not a public MCP schema or stable external HTTP API. `OBSERVATION_SCHEMA_VERSION = 1` is required on snapshots. Unknown snapshot identity enums and unknown component keys are rejected rather than guessed.

Existing ServerFS surfaces remain unchanged:

- MCP protocol/tools and errors are unchanged;
- `serverfs doctor` behavior/output is unchanged;
- Windows/macOS native service status is unchanged;
- Tunnel health endpoints are unchanged and remain in their existing private topology;
- Agent Bridge RPC/task APIs are unchanged;
- host-observability remains an external read-only publication recipe.

Phase C may project this contract through existing operator surfaces, but should not create a network endpoint merely because this model exists.

## 7. Security boundary

The new module has no I/O and no authority. It cannot observe a secret unless a future caller first violates the adapter boundary by passing secret-derived data into a bounded enum/value. The model further removes free-form component details and rejects arbitrary metric label values.

This does not replace adapter-level redaction. Future adapters still must avoid constructing common observations from raw paths, credentials, identities, payloads, provider messages, exception strings, or unrestricted configuration/log data.

## 8. Performance impact

Phase A performance baseline remains **Not measured**. Phase B adds no collector, poller, background task, network I/O, persistence, hot-path instrumentation, or exporter, so there is no new always-on observation loop to benchmark in this phase.

Before Phase D instruments Agent task/lease/recovery hot paths, the plan still requires reproducible baseline and before/after measurements. Phase B does not claim that requirement is satisfied.
