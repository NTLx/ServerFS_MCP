## Objective and method

Rebuild the entire current product narrative around v0.25.0, not historical milestones or keyword replacement. The conversation assistant owns every full-document reading, content decision, edit and reread. Do not delegate documentation work or review to a host Agent. Deterministic checks can supplement but never replace human-style reading. Inventory paths first; use repository code, version-matched manifests, parsers, tests and accepted ADRs to substantiate statements. A keyword search is allowed only for navigating implementation or checking residual consistency after full reads, not for deciding a document is reviewed.

For every file: (1) read from line 1 through EOF, following `next_start_line` until `has_more=false` (record revision and page ranges; restart if revision changes); (2) evaluate purpose, audience, complete narrative, prerequisites, examples, security, dependencies, failure/upgrade/retirement and remaining limitations; (3) check authoritative source and adjacent documents; (4) personally rewrite or justify no change; (5) reread the entire final file, compare bilingual peers, verify revisions/links and record status. A file read only as a source is not considered reviewed. Do not mark a file reviewed merely because build/lint passes.

## Readability and information architecture

Keep reader-facing content concise and navigable. Put the decision and prerequisite before the command; separate the normal path from optional components, advanced manual procedures and recovery. Provide one complete minimal example, then explain only changed settings for extensions. The website explains decisions and directs readers to the authoritative runbook; runbooks contain complete operational steps; Skills guide Agents using the same authoritative constraints. Prefer plain language and short sections; move old milestones and long acceptance transcripts into historical records. Do not remove required security conditions, supported limits or rollback guidance simply to reduce length. Bilingual copies convey the same decisions in natural language.

## Agent attention and runtime context

Agent-facing content has a different purpose from human runbooks. Use progressive disclosure: concise invocation description, exact task boundary, identity/preconditions and fail-closed gates before action, shortest correct procedure, platform/topic-specific references loaded only on demand, observable verification and bounded failure handling. Avoid broad default reading lists, duplicated reference material, historical evidence dumps, redundant restatements, giant logs and raw Base64. Keep the required packaging headings and standalone safety constraints. Prefer one canonical source per fact; preserve limits and authorization even when shortening. The Skills index is maintainer/navigation content and is not shipped in the portable archive, so essential rules must remain in each runtime Skill. Measure bytes/lines as simple size proxies, not an exact model-token estimate; check the actual workflow against the same task and source. Full-document review is the author's audit method, not a requirement that every runtime Agent load every manual.

## Canonical product facts established so far

1. Persistent HTTP deployment has a Core, zero or more supported ingress Connectors, optional host Bridge; local native stdio is a different transport. Direct HTTP is Core publication, not a third Connector. Connector credentials are not caller authorization. Named OpenAI HTTP uses static Core bearer admission; native HTTP admission and Linux auth-service deployment differ.
2. Stable named identities: `instance_id`, optional provider-scoped `connector_id` where supported, `bridge_id`; `disabled/owned/shared`. Native owned Bridge ID equals its Core ID. IDs are not credentials. Shared means same host, explicit per-Core grants; never manage another owner through the Core. Same UID/SID is not trust or adversarial isolation. Independent writable owners must not overlap.
3. Lifecycle independence is not dependency absence: stage dependencies, check readiness, component-specific operation, stop-safety refusal, quiescence and no implicit recreation of unrelated components. File capability can survive Bridge outage; Bridge requests fail safely. No guarantee of same-session SSE replay or all combinations being implemented/accepted.
4. Linux Docker-first, host user systemd Bridge; supplied overlays one service per provider per project, not native per-ID connector CLI. Explicit publication/internal-only and Bridge selection. Signed Linux attachment permits exactly one enabled alias in slot 01; extra disjoint file-only slots possible. Core and Bridge IDs are distinct nondefault IDs even for a dedicated owner. Initial grant provisioning accepts 1–32 Cores, not live append/rotation. Do not equate internal-only network isolation with all direct-HTTP egress isolation.
5. macOS Apple Silicon, arm64, macOS 27, APFS, signed SMAppService. Native stdio needs no signed persistent App. Same-provider IDs predeclared at staging for file-only/owned; owned uses private native socket/manifest/policy checks, not the shared v2 grant path. Shared Core CLI has separate staging/preflight/start/status/stop/unstage, exactly one bound Agent workdir, no Repo Ops and no Connector staging. Shared owner must be independently provisioned; no general owner installer in the named CLI. Named persistent Core snapshots disable shared file ingress; private HTTP env admits supported auth keys only and exact hostname,loopback authority. Preserve native stop guards.
6. Windows 11 x64, NTFS, installed Core/Native wheels, current-user Scheduler, Job Objects, Named Pipe/ACL; separate Bridge owner and worker environments. Initial helper generates bearer keys, copies policies, publishes grants/manifests without registration; up to 16 Cores per shared owner, exact effective policy subsets. Only initial bearer and explicit nonproxy runtime settings; manual path for specialized cases. Runtime/private configuration/connector helpers are create-only, preserve failed attempt evidence, not live rotation or automatic in-place upgrade. Component uninstall removes task, not private state.
7. Agent and Repo Ops independently enabled per workdir; Repo Ops never substitutes Agent; base 11, binary +2, Agent +10, Repo Ops +4; Jev advice only. Validate counts and capability details against actual tool declarations/tests in relevant batches.
8. Linux has 16 env slots with scalar overrides; native TOML supports up to 64 entries with shared `[defaults]` (file limits/hidden/binary), no Linux-style per-workdir binary/size/hidden/deny overrides. Linux direct binary transfer uses the slot override even if larger than the global default; optional file ingress uses min(slot limit, sidecar global ceiling). Native named macOS disables shared file ingress; Windows native implements direct binary transfer. Core HTTP Host allowlist is configured, not globally fixed to `serverfs-mcp:8000`. Use exact authorities.
9. HTTP API Key is one secret per Core, not caller identity or Tunnel identity. Linux env rotation requires scoped recreate, not restart; named OpenAI injects a Core bearer header, so test local Core denial separately from provider admission. Native initial configuration/staging is create-only, not in-place rotation. Packaged OAuth auth service is Linux Compose; native HTTP Resource Server may use an independently managed auth service (Windows manual configuration, macOS private HTTP input). Named OpenAI HTTP is static bearer, not OAuth. OAuth state is unique/private per deployment; never expose `/internal/introspect` to a public proxy route. Client preregistration needs an explicit read-only mount absent from the base OAuth overlay. Removing a principal blocks new identity admission but current access/refresh pairs are not rechecked against that allowlist; revoke current pairs or intentionally invalidate state. Restore can revive token state. Cloudflare origin is service DNS on Linux versus loopback on native, and provider registration is not caller authentication. Named Linux OpenAI health port is 8080, native may be allocated; successful startup poll does not prove current response delivery.
10. Distinguish supported source paths, installed/runtime readiness, historic acceptance, exact-release and public acceptance. v0.25.0 is publication-pending, not a stable release claim. Existing services are not implicitly migrated. No production actions, commit, push, tag, deployment or release in this review unless separately authorized.

Authoritative references already read in full: accepted native platform ADR, instance model ADR, Linux ingress/host-Bridge ADR, macOS multiple-Connector ADR (historical record; current parser is authoritative), Windows named operations runbook and release drafts; exact source checked: `src/serverfs_mcp/instance_identity.py`, `src/serverfs_mcp/darwin_instance_cli.py` parser section, `compose.http.yml`, `compose.cloudflare.yml`, six `deployment/linux/compose.*.yml` overlays. Later batches must inspect the relevant actual implementation rather than inherit assumptions.
