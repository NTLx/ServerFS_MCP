## Native stdio acceptance added in v0.15

macOS previously had real Darwin backend tests and CLI/platform-gate tests, but no process-level counterpart to Windows `test_windows_native_stdio.py` using the SDK stdio client against a real `serverfs serve` child. v0.15 adds:

```text
tests/test_darwin_native_stdio.py
```

The test starts `python -m serverfs_mcp.cli serve --config <temporary serverfs.toml>` on the supported Mac, connects with `mcp.client.stdio.stdio_client`, initializes a `ClientSession`, verifies the ServerFS identity/tool catalog, then calls `read_text_file` and `stat_file` through the real stdio protocol path.
