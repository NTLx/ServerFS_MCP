## Acceptance policy

Validate changed boundaries, not every permutation of platform, provider, transport and topology. Retain exact source/artifact provenance and security-negative evidence. A test executed against an earlier frozen source is reusable for the measured product behavior when the relevant implementation, native helpers, deployment scripts, dependency locks, configuration semantics and test assumptions remain equivalent. Documentation, test-only and ignore changes do not invalidate unrelated runtime measurements. If a product boundary or test assumption changes, rerun the affected checks. This does not replace the mandatory final-SHA automated CI/release workflow or artifact publication checks.

Do not report untested configurations as PASS. Record unverified combinations as limitations, not automatically as release blockers; investigate an actual failure in a changed supported path. For a new public MCP operation, exercise the MCP client surface, including authorization and negative cases; a local authenticated MCP endpoint is adequate for protocol semantics, while public ingress is a separate transport check. Never use private RPC alone as equivalent public-tool evidence. Keep private paths, raw provider requests, credentials and audit keys out of recorded evidence.

## Non-blocking follow-up coverage

The following are not required additional pre-release reruns for this scoped version when relevant inputs remain equivalent and existing deterministic/CI gates pass. Record them as unverified where appropriate; reopen a gate if new evidence identifies a regression or the corresponding product boundary changes.

- Repeating successful dual-workdir, native lifecycle, Cloudflare public and provider tests solely because of a documentation/test-only SHA change.
- Exhaustive provider × platform × connector × topology combinations, successful real-provider proxy/direct traffic beyond the existing controlled and rejection evidence, and OpenAI Tunnel/external direct HTTP live runs where transport implementation did not change. These are compatibility coverage, not a claim that every route is verified.
- Exhaustive browser/theme/device/keyboard testing for content-only website changes with unchanged layout, styles and dependencies, or checking every third-party link before the release/tag exists. Static build and local link integrity remain required; browser checks are required when rendering/layout or interaction changes, and a brief post-publication site smoke is useful.
- Generalizing host-specific diagnostic runners into portable tooling, new test infrastructure, additional failure injection, or investigating already accepted local Agent memory. Retain reproducible evidence and existing committed regression coverage; do not expand the product scope for these tasks.

No manual stable tag, unverified publication, production mutation or CI bypass. Unrun tests remain NOT VERIFIED, not PASS.
