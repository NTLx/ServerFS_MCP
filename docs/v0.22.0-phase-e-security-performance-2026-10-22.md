## 3. Linux Bridge resource acceptance

Command, run from `agent_bridge/`:

```bash
uv run python benchmarks/v022_diagnostics_resources.py --idle-samples 5 --interval 0.5
```

The benchmark starts a local `BridgeService` against a controlled temporary workdir/state/lock tree. It takes RSS and file/SQLite baselines after Bridge startup and recovery, fills the service recorder with a worst-case legal retained set, then samples idle RSS five times. It separately exhausts the closed operation catalog, including maximum finite JSON number widths, to prove whether the 1 MiB logical byte limit can be reached.

Measured on Linux `6.8.0-136-generic`, x86_64, Python 3.12.13:

- Maximum legal operation payload: **202 bytes**; maximum terminal seal payload: **156 bytes**.
- Even the conservative bound of 2,048 records each as large as the maximum operation is **413,696 bytes**, below 1,048,576 bytes. Therefore the frozen 1 MiB payload ceiling is unreachable under the closed catalog and record ceiling; it is not reported as a measured saturation.
- The conservative retained set reached **2,048 records / 410,806 logical payload bytes / 32 task slots**, which is **39.18%** of the nominal 1 MiB cap and 99.3% of the record-derived upper bound.
- Same-process Bridge RSS: **27,160 KiB baseline → 27,192 KiB retained**, a **32 KiB** increment; budget **4 MiB**, PASS.
- Five idle RSS samples were `[27192, 27192, 27192, 27192, 27192]` KiB; range **0 KiB**, PASS for no continuing growth during the 2.5-second observation interval.
- Controlled state files were identical before and after recorder population. No file was created; `state/state.sqlite3` stayed at **49,152 bytes** (growth **0 bytes**).
- Active thread count stayed **1 → 1**. Recorder call path is synchronous; no diagnostics background thread, timer or task is started.

The recorder's worst-case memory sample is a measured 32 KiB increment in this Linux process; the unreached 1 MiB payload figure is a mathematical upper-bound proof, not an RSS assertion.
