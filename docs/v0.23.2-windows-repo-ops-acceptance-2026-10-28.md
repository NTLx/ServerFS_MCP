## Implementation and local release gates

Windows Repo Ops adds native containment without changing the four-tool public contract or the no-Agent-fallback rule:

- repository roots reject NTFS reparse points/junctions before execution;
- Repo Ops children are created suspended, assigned to the Bridge-owned Job Object, then resumed;
- timeout, cancellation, or output overflow must converge the descendant process tree before the shared writer lease is released;
- if descendant cleanup cannot be proven, the operation fails closed and preserves the lease until an external Bridge generation restart;
- hardened Git-for-Windows paths remain non-interactive, use a narrow environment, neutralize hooks/signing/askpass/SSH overrides, and use native `NUL` where a hooks sink is required.

The target was a disposable local Git worktree with an existing local `file://` bare upstream; no production repository or network remote was used.

3. `commit_repo_changes` committed only that explicit file and returned commit `7054388f69c1e1fd52df4f3485dd2b3df017ad93`.

5. Final `inspect_repo(status)` reported a clean worktree.

Post-call Git verification proved local `HEAD`, the returned commit, and bare `refs/heads/main` were identical. The bare upstream contained only `refs/heads/main`, with no tag or other ref. No Agent task/provider session was created by Repo Ops.
