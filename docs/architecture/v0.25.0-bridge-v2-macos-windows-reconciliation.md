## Binding incompatibility found

The earlier Mac-only experimental modules (shared_v2_crypto, replay,
grants, owner_store, task_scope) are NOT a valid wire or persistence contract
for the current Windows v2 implementation.

Windows reference:
- Signed envelope: protocol_version, bridge_id, core_id, key_id, request_id,
  method, params, policy_revision, issued_at, nonce, signature.
- MAC: HMAC-SHA256 of canonical JSON request with sorted keys, ASCII escape,
  compact separators and no non-finite numbers; signature as lowercase hex.
- Nonce: 32–64 lowercase hex characters, timestamp integer seconds.
- Authorization: per-Core method/workdir plus SHA-256 of the full live Bridge
  workdir policy, including canonical host root, read-only and Agent/Repo Ops.
- Credentials: existing private owner state/core-grants.json, with strictly
  validated owner-provided secret_hex and explicit non-automatic provisioning.
- Task isolation: durable Core owner and exact workdir check in TaskStore.
- v2 continuation and idempotency fields in task.submit currently DENIED,
  pending an agreed cross-platform namespace and resume contract.

Earlier Mac experiment:
- Different grant_id and base64 payload envelope, length-prefixed MAC input,
  millisecond timestamps and SQLite owner grant / per-grant key files.
- Separate experimental sidecar for task ownership and Core-scoped idempotency.

These are not interoperable. Do NOT combine the Mac experimental crypto,
credential, replay or TaskStore code with Windows core_grants verifier.
Do NOT expose either experimental path via a mixed v1/v2 IPC listener.

## Controlled convergence sequence

1. Freeze the Windows reference contract in a jointly reviewed ADR and
   cross-platform test vector. Confirm any Windows upstream changes before
   continuing; do not invent another Mac-specific v2 wire format.
2. Port existing Windows core_grants_private.py, relevant TaskStore nonce/task
   owner contract and explicit BridgeConfig v2-only gate to Mac by narrow
   source reconciliation and tests, retaining existing v1 defaults.
3. Replace/remove the now-obsolete Mac-only experimental v2 modules and
   their TaskStore optional sidecar integration AFTER replacement features
   and regression gates have passed. They remain source-only and must never
   be imported by real RPC in the meantime.
4. Add authenticated Core client binding with Mac-specific private-state
   and launchd/SMAppService ownership checks. Keep independent Bridge
   lifecycle and separate v2-only IPC socket.
5. Test two disjoint Core policies against one synthetic shared Bridge on
   native Mac, including revoked key, nonce replay/restart, task ownership,
   runtime discovery and Repo Ops negative cases.
6. Complete unified Windows/macOS/Linux topology and isolated public
   Cloudflare/OpenAI MCP E2E. No production service replacement before gates.

## Remaining issues explicitly not resolved

- Windows v2 currently refuses client-supplied task continuation and
  idempotency fields, whereas the Mac exploratory sidecar allowed scoped
  idempotency. Keep the Windows fail-closed contract until a joint decision.
- A tested cross-platform secret provisioning and rotation owner workflow
  is still required. The Mac experimental SQLite key registry is NOT a
  substitute for Windows protected core-grants.json.
- The Windows source is under active parallel development; copied modules
  require revision reconciliation before Git integration.
- No Git commit/push/fetch/tag, production service mutation, live Agent job,
  native shared v2 service registration or public MCP test happened here.

**Gate conclusion:** Windows common CoreGrantVerifier is a workable Mac
source-level baseline. The divergent Mac experimental protocol is
superseded for intended v0.25.0 integration, but remains unexecuted and
unremoved until code replacement is safely verified.
