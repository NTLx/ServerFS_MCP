## Protocol and conformance

- Phase B real-loopback evidence in [`v0.20.0-phase-a-probes-2026-10-21.md`](v0.20.0-phase-a-probes-2026-10-21.md) established that one stateful (`stateless_http=False`) Streamable HTTP app serves both legacy `2025-11-25` session lifecycle and modern `2026-07-28` requests without a session. Modern request `_meta` and `Mcp-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` headers were observed. The app also served the SDK auto-discovery path.
- Phase C pins the official MCP Conformance source at `232a9014457eaf4c59559916e3d616d2f7f28f05` because stable `v0.1.16` does not support `--requirements`. Exact-SHA Container CI completed its “Run full reports and frozen hard gates” step successfully for both requirement sets and uploaded reports. The recorded aggregate results are 8/30 scenarios and 40 pass / 22 fail checks for `2025-11-25`, and 12/37 scenarios and 77 pass / 26 fail checks for `2026-07-28`; these full-suite totals include undeclared capabilities and fixed-fixture/Host assumptions and are report evidence, not the hard-gate verdict. The reviewed applicable hard-gate set had 20 scenarios with exit code 0 and no `FAILURE` checks. One caching check was `SKIPPED` for an empty resource fixture; two InputRequiredResult checks emitted `SHOULD` warnings, which are not passing evidence for that recommended behavior.
- The pinned conformance gate is integrated in CI. The source reports and scenario-level evidence are retained as CI artifacts; this repository checkout does not contain those uploaded raw artifacts.
