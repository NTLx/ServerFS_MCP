## Binary-transfer configuration

v0.9.0 makes `SERVERFS_MAX_BINARY_TRANSFER_BYTES` the single documented global byte ceiling for:

- native binary download;
- native binary upload;
- ChatGPT/OpenAI file-parameter ingress fetch.

The legacy `SERVERFS_FILE_INGRESS_MAX_BYTES` is compatibility fallback only when the unified
setting is absent/empty. If both are present, the unified setting wins. The default remains 8 MiB.

Per-workdir `WORKDIR_XX_MAX_BINARY_TRANSFER_BYTES` continues to tighten final workdir
publication without making the isolated ingress sidecar workdir-aware.

Focused root tests covering this contract passed as part of the 824-test root suite.

## Release interpretation

The v0.9.0 implementation satisfies the intended product boundary:

- ServerFS can discover native model metadata where the runtime exposes a stable mechanism;
- unsupported discovery is explicit rather than fabricated;
- Jev advice is pre-submit and advisory only;
- explicit model selection is request-scoped;
- omission preserves native provider behavior;
- requested model is durable task/idempotency/manifest evidence;
- no ServerFS model default/configuration surface was introduced;
- no automatic model fallback was introduced;
- the global binary-transfer/file-ingress limit now has one public configuration source.
