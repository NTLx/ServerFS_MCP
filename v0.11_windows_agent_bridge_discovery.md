## 1. Executive Summary

1. **The v0.10 native Windows ServerFS baseline on this machine is green.** `serverfs 0.10.0` +
   `serverfs-windows-native 0.10.0` on uv-managed CPython 3.13.3 AMD64; `serverfs doctor` exit 0 with
   `0 FAIL, 0 WARN`; `ruff check` and `ruff format --check` pass; the 15 Windows-targeted test files
   run `359 passed, 3 skipped` in 13 s. `VERIFIED`.
2. **The Agent Bridge is not portable as-is, and the blocker is narrow and well separated.** Four
   Bridge subsystems are Linux-only: UDS transport (`protocol.py:54`), peer identity
   (`protocol.py:240-252`), the `fcntl.flock` writer lease (`leases.py:5,106`) and POSIX
   ownership/mode guards (`store.py:43`, `recovery.py:37-49`, `result_spool.py`, `protocol.py:61-71`).
   The task model, state machine, event envelopes, manifest, spool, idempotency, approvals/questions,
   model discovery/override and the SQLite persistence *format* are provider-neutral and
   platform-neutral in logic. `VERIFIED` by source.
3. **Windows already provides an equal-or-stronger replacement for the two hard platform
   primitives, and both were measured working on this machine.** (a) Named pipes round-trip and the
   server side can read the **client PID and client session ID**
   (`win32pipe.GetNamedPipeClientProcessId` → observed PID equal to the connecting process, `MATCH`);
   (b) `msvcrt.locking` byte-range locks are **cross-process exclusive** (second process blocked).
   `SO_PEERCRED` semantics are therefore reproducible; they are *not* reproducible via AF_UNIX,
   because this CPython exposes no `socket.AF_UNIX` at all. `VERIFIED`.
4. **Runtime availability is asymmetric across the three runtimes.** Codex is fully usable on this
   Windows host (CLI 0.159.2, managed app-server daemon *running* at 0.160.0, `codex login status`
   = "Logged in using ChatGPT") and **every app-server method/field the current adapter assumes still
   exists**, proven against the protocol JSON Schema that the installed CLI itself generated. Claude
   Code runs natively (2.1.285) but **`claude-agent-sdk` publishes no Windows wheel** (macOS +
   manylinux + sdist only) → hard environment blocker. Qoder CLI works (`1.1.65`, authenticated,
   `--list-models` returns a catalog) and **`qoder-agent-sdk` does ship a `win_amd64` wheel**, but
   neither SDK is installed here, so their APIs are `NOT TESTED`. `VERIFIED`.
5. **The native MCP process is structurally Agent-disabled, and by three independent mechanisms**, not
   one: no agent fields exist in the native TOML schema; `cli.py` builds `Settings` without
   `agent_bridge_enabled`; and even if the flag were forced on, `agent_tools.py` would crash on
   `fdio.py:34` (`os.O_DIRECTORY`) rather than refuse cleanly. Native workdirs additionally
   **cannot take a writer lease at all** — `workdirs.py:134-147` returns sentinel slot `0` and
   `agent_leases.py:32-33` refuses anything outside 1..16. `VERIFIED`.
6. **Codex's own Windows transport is the open design question.** The running daemon advertises
   `socketPath = ~/.codex/app-server-control/app-server-control.sock`, i.e. Codex (Rust) uses an
   AF_UNIX-shaped endpoint that CPython cannot reach (`socket.AF_UNIX` absent). Two Codex-supplied
   Windows-viable seams exist and are documented in the installed CLI: `codex app-server proxy`
   (relays stdio bytes to the control socket) and `--listen ws://IP:PORT`. Neither is exercised yet.
   `VERIFIED` that they exist; `NOT TESTED` whether they work here.
7. **The largest non-obvious cost is the test suite, not the Bridge.** The root pytest suite does not
   even collect on Windows: 12 collection errors (`fcntl`, `os.O_DIRECTORY`, module-scope
   `os.geteuid`). Of the 941 collectible tests, 122 fail + 3 error on Windows, concentrated in
   `test_agent_deployment` (38), `test_agent_tools` (22), `test_edit_text_file` (14),
   `test_tunnel_proxy_deployment` (12). `agent_bridge/tests/` (138 tests) is not importable here at all.
   `VERIFIED` by execution.
8. **Recommended v0.11 boundary (§24)**: native Bridge process, named-pipe IPC + PID/SID peer
   identity, alias-keyed (not slot-keyed) writer lease, NTFS-ACL-based state-directory guards, Codex
   as the single first runtime, Qoder second, Claude deferred until a Windows SDK wheel exists.

No BLOCKED item stopped the investigation; two sub-questions could not be answered inside the
read-only boundary and are listed as `NOT TESTED` in §23. No secret, credential, host path, proxy
endpoint or workdir root is recorded in this report.

**zero** hits. `mutations.py` (the fdio+flock pipeline) is not on the Windows path at all.

## 22. v0.11 Design Decisions Required

Only items the investigation shows are genuinely open, with the evidence that forces the decision:

1. **Windows local IPC primitive.** Named pipe vs loopback TCP vs (rejected) AF_UNIX-through-
   CPython. Evidence: `socket.AF_UNIX`/`SO_PEERCRED`/`asyncio.*_unix_*` all absent (§15.1); pipe
   roundtrip + client PID measured working (§15.2). Decision includes pipe name/ACL exposure,
   message vs byte mode, and whether the 1 MiB envelope limits (`protocol.py:19-20`) carry over
   unchanged.
2. **Peer identity semantics on Windows.** Client PID + session vs full SID via impersonation vs
   an additional token. Must preserve "measure, then assert; never synthesize"
   (`AGENTS.md:57-79`, `protocol.py:240-252`) and must not become "trust the pipe name". Note the
   `hasattr(socket,'SO_PEERCRED')` fail-closed branch has no test today (§19 gap 3).
3. **Writer-lease primitive.** `msvcrt.locking` vs `LockFileEx` via the Rust kernel (which currently
   exposes no lock at all, §16) vs a mutex object. Must keep: reader opens without creating
   (`agent_leases.py:38-48`), exclusive-for-the-whole-active-turn, live-lease precedence over the
   recovery guard, release only after cleanup (`dev_plan_v0.7.md:87-121`).
4. **Lease/guard keying.** Numeric slot 1..16 → alias. Forced by `workdirs.py:134-147` +
   `native_config.py:196-215` (native workdirs have no slot) and by
   `dev_plan_v0.10.md:1601` (must not restore fixed Docker slots). This is the one decision with
   cross-boundary blast radius: `agent_bridge/.../config.py:154-156`, `leases.py:68-69`,
   `recovery.py:25`, `tools.py:142`, Bridge config render, and both test suites.
5. **Windows state directory convention.** Reuse `serverfs_data_dir()` (`%LOCALAPPDATA%\ServerFS`,
   `SERVERFS_DATA_HOME` override, fail-closed if `LOCALAPPDATA` missing) or define a
   `serverfs-agent-bridge` sibling; and how state/spool/active-guard subdirs are derived. Explicitly
   *not* a mechanical `~/.local/state` translation (`config.py:245`).
6. **State-directory authorization.** NTFS ACL/owner model replacing `st_uid != os.getuid()` and
   `st_mode & 0o077` (`store.py:43`, `recovery.py:37-49`, `result_spool.py:31,103`,
   `protocol.py:149`), given measured `st_uid=0`/`mode=0o777` degeneracy (§15.3, §18).
7. **Native config surface.** Whether Agent fields live in `[server]`, a new `[agent]` table and/or
   per-`[[workdirs]]` `agent_mode`/`agent_runtimes`, and how to handle the asymmetric unknown-key
   behaviour (§9A: top-level unknown keys silently ignored today) without silently converting
   previously-ignored config into a startup error. Also whether the native Bridge endpoint is
   `serverfs.toml` (TOML) or keeps the Bridge's own JSON config (`config.py:153`) — two config
   surfaces must be reconciled.
8. **Native Bridge lifecycle model.** No systemd, no Windows service, no Task Scheduler
   (`AGENTS.md:63-67`; `dev_plan_v0.10.md:91` non-goal) — so: supervisor-managed child like
   `supervisor.py`, `serverfs agent` subcommand, or operator-started process; plus graceful-stop and
   crash-restart semantics, and Job Object containment of provider children (§17).
9. **Runtime set for the first Windows release.** Codex-only vs Codex+Qoder vs all three, given D-bucket
   facts (Claude wheel gap; Qoder wheel exists; Codex transport seam needed).
10. **`relative_cwd` path grammar on Windows** (`PurePosixPath` at `policy.py:132`,
    `service.py:1469-1475`) — keep POSIX-relative vocabulary (recommended for contract stability) or
    accept native separators. Public-tool-contract decision.
11. **Whether Agent tools become importable-but-refusing on Windows** (fix `fdio.py:34` import-time
    evaluation + make `agent_tools` import lazily behind a platform guard) — required to turn today's
    "crash" into the documented "fail closed", and also unlocks 8 root test modules.
12. **CI shape.** Which Windows CI job runs which subset (the four portable Bridge test modules +
    the v0.10 `test_windows_*` set are the natural first slice, §19), given today's windows-native
    evidence is Linux-host-only.

Deliberately **not** listed as decisions (no evidence they need changing): RPC envelope and
protocol version, tool counts/surface, manifest schema, approval decision vocabulary, Jev advisory
limits, transport-security settings for Streamable HTTP, file-ingress boundaries.
